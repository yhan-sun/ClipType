# ClipType v0.2.0-beta.7

`v0.2.0-beta.7` is a UI/UX correctness and usability prerelease. It keeps the
beta.6 Rust injection behavior and privacy boundaries while bringing the macOS
Flutter settings/menu-bar presentation in line with the actual product state.

## macOS Flutter UI/UX

- Replaces implementation-oriented navigation with **Overview**, **Input**,
  **Shortcuts**, **System**, and **About**.
- Overview shows enabled state, Accessibility, registered shortcut readiness,
  selected mode, the next setup action, and the latest content-free session
  result.
- The settings-window Start action explains once that ClipType will hide the
  window and return focus to the previously active app before input begins.
- A missing Accessibility permission no longer causes the Flutter Trigger
  command to open System Settings automatically; remediation remains an
  explicit user action.
- Closing the macOS Settings window explains once that ClipType remains active
  in the menu bar.

## Input settings

- Code mode now exposes the safe corrected-typo probability already supported
  by the beta.6 Rust coordinator.
- Code guidance states that temporary typo keys exclude brackets, quotes,
  slash, navigation, and non-ASCII source characters.
- Clipboard mode hides keyboard pacing controls that cannot affect it.
- Auto, Keyboard, and Code show only settings relevant to their behavior.
- Temporarily empty/incomplete number edits remain local and no longer become a
  persisted zero value.
- Optional corrected-typo guidance uses caution styling instead of the same
  error styling as a failed save or permission failure.

## Shortcuts and menu bar

- Complete Trigger/Stop candidates are applied through the existing
  transactional native replacement path; conflicts leave the previous working
  pair active.
- Candidate availability is reset while editing and shown at the recorder,
  avoiding stale Available feedback.
- The menu bar distinguishes Ready, Typing, Stopping, Disabled, Permission
  Required, Shortcut Unavailable, and Runtime Unavailable states.
- Start/Stop menu commands are enabled only when meaningful.
- A login item waiting for macOS approval is shown as pending rather than
  indistinguishably checked.
- Accessibility becomes an explicit Grant/Manage action based on current state.

## Build identity and diagnostics

About reads version and build number from the running app bundle. The beta.7
Flutter package is `0.2.0-beta.7+6`; the UI no longer contains the stale
hard-coded beta.2 version. Bundle metadata also identifies architecture,
preview channel, ad-hoc signing, and notarization status.

The About diagnostics block is selectable but does not write a new value to the
clipboard. It contains only build information and fixed runtime categories; it
does not include clipboard/input text, destination values, selected text,
document names, or window titles.

## Privacy and safety

No clipboard history, telemetry, network transport, target-content reads,
window-title reads, or automatic permission bypass is added. Flutter and Swift
continue to receive only settings and content-free state categories. Rust
remains the authority for session reservation, backend selection, target and
modifier revalidation, pacing, cancellation, and terminal outcomes.

## Windows x86_64

The standard public-release workflow rebuilds and revalidates the Windows
x86_64 artifacts from the exact tagged `main` commit, produces SHA-256
manifests, keyless Sigstore bundles, and GitHub artifact attestations. This
release does not add an Authenticode trusted-publisher identity.

## macOS Apple Silicon testing preview

The supplemental macOS artifact remains an **Apple Silicon arm64 testing
preview**. The exact-main workflow builds, ad-hoc signs, installs and
launch-smokes `/Applications/ClipType.app`, packages ZIP/DMG assets, verifies
checksums, and attaches them additively after the prerelease exists.

It is not Developer ID signed, notarized, stapled, Universal 2, Intel/Rosetta,
or a general macOS compatibility claim. Hosted CI still does not substitute for
persistent user-granted Accessibility consent or a physical human VS Code /
Monaco session.
