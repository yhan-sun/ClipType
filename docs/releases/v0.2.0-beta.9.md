# ClipType v0.2.0-beta.9

`v0.2.0-beta.9` is a release-orchestration and repository-consistency prerelease built on the beta.8 product line. It keeps the beta.8 production input behavior while hardening the cross-platform publication handoff and aligning normative documentation with the currently shipped architecture.

## Release handoff hardening

- The macOS Apple Silicon publication job now waits until both the GitHub prerelease and its tag ref are visible and bound to the exact `GITHUB_SHA` before it verifies or uploads supplemental macOS assets.
- This closes the Release/tag visibility race observed during the beta.8 publication, where the Release became visible briefly before the tag ref could be queried.
- Supplemental macOS assets remain additive-only: existing asset names are refused, and published files are re-downloaded and verified after upload.
- Windows public-release dry-runs now cancel only stale pull-request runs for the same ref so an old candidate cannot serialize ahead of the newest candidate. Real `main` publication runs remain non-cancelling.

## Repository and contract reconciliation

- README and normative architecture, platform, compatibility, testing, injection, technology, roadmap, and documentation-index material are aligned with the published beta.8/beta.9 architecture.
- Flutter/AppKit remains the sole macOS Apple Silicon front end; the older P3 Universal 2/shared-Slint macOS plan is historical and superseded.
- Clipboard delivery documentation now matches the production contract: ClipType uses the already-current clipboard with content-blind revision guarding and does not write, clear, replace, restore, or silently take ownership of clipboard contents.
- Code-mode verification remains keyboard-only and explicitly forbids a Paste fallback.
- Hosted CI evidence remains separate from physical named-application, persistent Accessibility-permission, and trusted Apple-distribution evidence.

## Product behavior

There is no intended production injection-policy change from beta.8. The existing safeguards remain in force:

- destination evidence is captured before clipboard acquisition;
- one active session only;
- bounded current-clipboard reads and dispatch;
- per-action target, cancellation, and modifier checks where required;
- conservative complete/none/partial/progress-unknown classification;
- no automatic retry after partial or unknown native progress;
- no privilege bypass or automatic elevation;
- content-free diagnostics with no clipboard or destination plaintext.

The macOS Flutter bundle version is `0.2.0-beta.9+8`.

## Windows x86_64 public beta

The release workflow rebuilds the exact merged `main` commit, reruns workspace check/test/Clippy, builds the optimized executable, verifies the distributable privacy boundary, generates dependency/build metadata and SHA-256 manifests, signs primary assets with keyless Sigstore, generates GitHub artifact attestations, verifies the signatures, and creates the prerelease only if the beta.9 tag/release do not already exist.

Authenticode trusted-publisher signing is not configured, so Windows reputation or SmartScreen warnings may still appear.

## macOS Apple Silicon testing preview

The macOS artifact remains an **Apple Silicon arm64 testing preview**. Hosted CI builds, ad-hoc signs, installs and launch-smokes the application, packages ZIP/DMG assets, verifies checksums and source identity, then attaches the exact assets to the beta.9 prerelease only after the Windows-created prerelease and tag are visible at the same source commit.

It is not Developer ID signed, notarized, stapled, Universal 2, Intel/Rosetta, or a broad named-application compatibility claim. Physical Accessibility, real-application input, shortcut/focus/cancellation behavior, and trusted Apple distribution remain tracked separately.

## Remaining physical acceptance

- Windows representative interactive compatibility remains tracked by Issue #33.
- macOS physical interactive acceptance and trusted Apple distribution remain tracked by Issue #61.

These open evidence items do not change the automated beta.9 artifact identity or CI result, and they must not be inferred from hosted runners.

## Privacy and rollback

No clipboard history, telemetry, clipboard-content network transport, target-text logging, window-title logging, permission bypass, or release-asset overwrite is added.

Published beta.8 assets remain immutable. If beta.9 needs remediation, publish a newer beta rather than moving the beta.9 tag or replacing its public bytes.
