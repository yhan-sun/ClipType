# ClipType v0.1.0-beta.1

ClipType's first public Windows beta turns the proven clipboard-to-input vertical slice into a daily-usable tray utility.

## Included

- native Win32 tray shell and reviewed global trigger/cancel hotkey presets;
- explicit `keyboard`, `clipboard`, and capability-gated `auto` modes;
- bounded Unicode keyboard injection and revision-guarded current-clipboard paste;
- strict versioned per-user settings with backup recovery;
- current-user start-at-login support;
- per-user install and uninstall scripts that require no elevation;
- content-free status, diagnostics, privacy-sentinel checks, and bounded shutdown;
- Windows Server 2022 and Windows Server 2025 x86_64 CI compatibility coverage.

## Compatibility declaration

This beta supports interactive x86_64 editions of Windows that provide the Win32 APIs used by ClipType. Windows 11 x64 is the recommended client platform. Windows 10 22H2 x64 remains an API-compatible best-effort platform, but the operating system is outside standard Microsoft support and should be kept on an applicable security-update program.

The compatibility statement covers ordinary desktop applications that accept standard Unicode `SendInput` events or the ordinary `Ctrl+V` paste command. It is not a universal per-application guarantee. ClipType intentionally stops or reports a limitation when Windows cannot provide sufficient target evidence, the target is elevated above ClipType, modifiers conflict, the clipboard changes before paste, or native progress is partial/unknown.

Not supported in this release:

- 32-bit Windows;
- Windows on ARM64;
- Server Core or non-interactive sessions;
- automatic elevation or injection across Windows integrity boundaries;
- an exact logical-field guarantee inside applications that expose multiple fields through one shared render host;
- clipboard formats or transformations that require ClipType to rewrite and restore the clipboard.

## Install

1. Download `ClipType-v0.1.0-beta.1-windows-x86_64.zip`.
2. Verify `SHA256SUMS.txt`, its Sigstore bundle, and the GitHub artifact attestation.
3. Extract the archive.
4. Run `install.ps1` from PowerShell. The default installation is per-user and does not require administrator privileges.

The archive also supports portable execution of `cliptype.exe`.

## Signature and provenance

The release archive and checksum manifest are signed using Sigstore keyless signing from the repository's protected GitHub Actions release workflow. GitHub artifact attestations bind the published files to the workflow run and source commit.

The executable is **not Authenticode publisher-signed** in this beta because no trusted Windows code-signing certificate is configured. Windows reputation or SmartScreen warnings may therefore appear. The Sigstore bundle, checksums, and GitHub attestation provide cryptographic source provenance, but they do not make Windows display a trusted publisher identity.

Example verification after installing Cosign and GitHub CLI:

```powershell
Get-FileHash .\ClipType-v0.1.0-beta.1-windows-x86_64.zip -Algorithm SHA256
cosign verify-blob `
  --bundle .\ClipType-v0.1.0-beta.1-windows-x86_64.zip.sigstore.json `
  --certificate-identity "https://github.com/yhan-sun/ClipType/.github/workflows/windows-release.yml@refs/heads/main" `
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com" `
  .\ClipType-v0.1.0-beta.1-windows-x86_64.zip
gh attestation verify .\ClipType-v0.1.0-beta.1-windows-x86_64.zip --repo yhan-sun/ClipType
```

Always compare the archive digest with the entry in `SHA256SUMS.txt` before installation.

## Privacy and safety

ClipType does not persist clipboard text, collect clipboard history, transmit clipboard content, read focused-field contents, or log window titles. Clipboard mode pastes the user's current clipboard only after a content-blind revision check; it does not replace, clear, or restore the clipboard. Partial or unknown native input is never blindly retried.

## Known limitations

- Hotkey preset changes apply after a controlled restart.
- Standard paste semantics are owned by the destination application; rich-text targets may choose another existing clipboard format.
- Terminal line breaks can be operational commands. Review clipboard content before triggering input in terminals or administrative tools.
- A normal-integrity ClipType process does not inject into a higher-integrity target.
- Application-specific compatibility reports remain welcome even when the underlying Win32 mechanisms are supported.

## Upgrade and uninstall

Re-running `install.ps1` updates the per-user executable and preserves the selected startup setting. `uninstall.ps1` removes product-owned installation and startup state. Pass `-RemoveSettings` to remove the per-user configuration as well.
