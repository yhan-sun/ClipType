# Security and Privacy Model

## Security posture

ClipType deliberately handles data that may contain passwords, API tokens, private messages, source code, personal information, and one-time codes. Clipboard and injected text are therefore classified as **sensitive by default**.

Privacy constraints are architecture requirements, not optional settings.

## Data lifecycle

Default flow:

```text
OS clipboard -> ephemeral process memory -> injection backend -> target application
```

Clipboard text MUST NOT enter persistent storage unless a future explicitly scoped feature and ADR changes this model. V1 has no clipboard history.

## Logging rules

### Forbidden
- clipboard plaintext;
- injected plaintext;
- prefixes/suffixes/samples of content;
- focused field contents;
- raw user keystroke capture;
- long-lived content hashes intended to correlate clipboard values across sessions;
- secrets in panic/crash annotations.

### Allowed
- payload length or coarse length bucket;
- platform/backend;
- non-sensitive target application/process identity;
- timing/duration;
- capability/permission state;
- result/error category;
- cancellation/focus-abort flags.

## Network rule

V1 core functionality requires no network access. No clipboard/injected text may be transmitted. Update checking, telemetry, or remote features require separate review and must remain content-blind.

## Threat model

### Accidental injection into the wrong target
Mitigations:
- explicit manual trigger by default;
- capture target before injection;
- focus guard during multi-chunk operations;
- immediate cancellation;
- one active session maximum.

### Clipboard race during paste mode
Another process/user may change the clipboard between temporary write and restoration.

Mitigations:
- generation/ownership evidence where possible;
- do not overwrite a newer external clipboard during restoration;
- typed cleanup errors;
- bounded transaction timing.

### Sensitive-data leakage through diagnostics
Mitigations:
- structured allowlist logging;
- tests/review checks against plaintext logging;
- content-free crash context.

### Privilege abuse
Mitigations:
- main application runs unprivileged;
- do not bypass Windows UIPI/macOS consent/Wayland policy;
- isolate Linux uinput privilege into a minimal helper only if needed;
- minimal local protocol and caller authorization.

### Synthetic input surprise/denial of control
Mitigations:
- manual activation;
- visible injecting state;
- cancellation;
- bounded event chunks;
- fail closed on target change.

### Malicious clipboard content
Clipboard text is data, not commands.

Mitigations:
- no shell evaluation;
- no template/macro evaluation in V1;
- explicit handling of control characters;
- platform paste chord is generated by code, not concatenated shell strings.

## OS permission behavior

Permissions are explained and requested only when needed. Denial is a valid state. ClipType must remain controllable and provide remediation guidance without repeated coercive prompts.

## Memory handling

Rust reduces accidental memory-safety bugs but does not guarantee secret erasure. V1 minimizes lifetime and copies of plaintext. Explicit zeroization may be evaluated for bounded buffers, but the project must not make false guarantees about eliminating copies held by OS clipboard APIs, GUI frameworks, or target applications.

## Crash handling

Crash reports and minidumps can contain memory. Distribution builds should configure crash collection conservatively, document what is captured, and never automatically upload raw dumps containing process memory without explicit informed consent.

## Supply chain

Dependencies that touch clipboard/input/FFI/serialization or privileged helpers receive heightened review. Lockfiles, reproducible build practices where practical, provenance/signing, and automated vulnerability checks are release requirements as the implementation matures.

## Security invariants checklist

A release is blocked if any are false:

- [ ] no clipboard/injected plaintext persistence by default;
- [ ] no plaintext logging/telemetry;
- [ ] no security-boundary bypass;
- [ ] explicit-trigger default preserved;
- [ ] cancellation works for long injections;
- [ ] focus safety meets the documented platform guarantee;
- [ ] clipboard restoration does not overwrite a newer external value;
- [ ] privileged helper, if present, is minimal and reviewed.
