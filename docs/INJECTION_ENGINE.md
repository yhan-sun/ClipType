# Injection Engine Specification

## Purpose

The injection system converts one explicit user trigger plus current clipboard text into a bounded, cancellable attempt to deliver text to the destination intended at trigger time.

The design separates:

- **pure policy**: validation, normalization, planning, state-transition and retry decisions;
- **live coordination**: session slot, native ports, worker lifecycle, cancellation/focus checks, and final cleanup.

There must not be two competing live state machines in core and app.

## Modes

- `keyboard`: native synthetic text/key events. Text is normalized into semantic actions and dispatched one bounded action at a time with target/modifier/cancellation checks, true characters-per-second pacing, and bounded per-action jitter.
- `clipboard`: guarded use of the user's already-current clipboard. The plan requires a known content-blind revision witness and sends one balanced native Paste chord only after the revision and destination are revalidated. ClipType never writes, clears, replaces, restores, or takes ownership of clipboard contents.
- `code`: explicit keyboard-only path for source code. It skips leading indentation, types opening delimiters and ordinary quotes, and uses cursor-right actions to pass over matching pairs already generated by the destination editor. A closer that is the first non-indentation character after a source line break uses a dedicated right-navigation action: the planner avoids a redundant Return once the editor has moved that generated closer to its own line, then the platform crosses the existing line boundary and moves to that line's end. Consecutive matching closers on that source line are consumed as one group. Empty multiline pairs retain the Return needed to create their body and closing lines. The live coordinator drains these source actions through a strict FIFO queue and inserts bounded, cancellable settle barriers so asynchronous editor auto-pair/auto-indent work can complete before dependent navigation. Pair-aware behavior is restricted to `()`, `{}`, `[]`, `""`, and `''`. Brackets inside ordinary quoted strings and recognized comments are literal; Python-style triple-quoted runs (`"""` and `'''`) are typed explicitly. Markdown triple-backtick fences and single backticks are literal. Code mode never reads destination-editor text and never falls back to Paste.
- `auto`: pure capability/Unicode-shape/size-based selection. Non-ASCII text prefers revision-guarded paste when available; otherwise Auto may use the proven Unicode keyboard path. The configured threshold remains the size crossover for otherwise keyboard-friendly text. One backend is frozen before dispatch.

Explicit modes never silently change backend.

## Trigger order

Destination evidence is captured before potentially contended clipboard work:

1. receive explicit trigger;
2. atomically reserve the one-session slot or return busy;
3. capture initial target evidence immediately;
4. start the bounded worker lifecycle;
5. wait for trigger modifiers to settle safely;
6. acquire bounded current clipboard text plus content-blind revision evidence;
7. validate/normalize text and capabilities;
8. create an immutable keyboard, clipboard, Code, or Auto-selected plan;
9. revalidate target, modifiers, cancellation, integrity, and—when pasting—clipboard revision before dispatch;
10. dispatch bounded native actions;
11. publish a content-free result and release the session slot.

The macOS settings-window Trigger button first hides the settings window and yields a bounded handoff so the previously active application can regain focus. The global shortcut path does not need this handoff. Both paths capture and revalidate the destination through the same coordinator policy.

## Planner

Inputs include requested mode, validated text properties, capabilities, target evidence, pacing settings, permission/integrity evidence, focus policy, modifier policy, and checkpoint policy.

Conceptual output:

```text
backend
focus_policy
native_action_bound
checkpoint_policy
characters_per_second
jitter_percent
corrected_typo_probability
modifier_policy
newline_policy
tab_policy
capability_assumptions
```

A plan is immutable during a session. If an assumption becomes false, fail safely rather than silently switching behavior.

## Text model

Clipboard text is validated into semantic atoms before native translation:

- printable Unicode scalar;
- normalized line break;
- Tab when allowed;
- rejected unsupported control character.

Requirements:

- preserve Unicode scalar order and combining marks;
- use one documented CRLF/CR/LF normalization rule;
- reject unsupported controls explicitly;
- keep platform-native event arrays out of core policy;
- represent supplementary Unicode as one semantic element even when the adapter emits multiple UTF-16 units;
- never invent exact text progress from native event counts when that mapping is uncertain.

## Pure transition model

Core may express deterministic transitions such as:

```text
Idle -> CaptureTarget -> Preparing -> ReadyToDispatch -> Injecting
                                                     -> Cancelling/Aborting
                                                     -> Failed
terminal state -> Finalize -> Idle
```

Core decides valid transitions and outcome policy. The application layer owns the live instance, ports, worker, channels, cancellation token, and cleanup.

## Single-session rule

At most one active session exists. Reservation happens before worker creation. A second trigger returns `busy`; it is not queued and does not implicitly cancel the active session.

## Focus guard

Initial target evidence is captured at trigger time. Before native dispatch and again at every later keyboard/Code checkpoint:

- recapture/compare available target evidence;
- stop on known change or target disappearance;
- under strict policy, stop if evidence required by the original guarantee becomes unavailable or ambiguous;
- never refocus an old target or adopt a new target to finish the payload.

The guarantee is limited by platform evidence. Several logical fields may share one native render-host identity, so compatibility documentation does not claim exact-caret identity without evidence.

## Cancellation

- native message loops remain responsive during injection;
- cancellation signals the active token without waiting for the worker;
- keyboard and Code paths check cancellation before each bounded semantic/native action and during cancellable waits;
- clipboard mode checks cancellation before its single Paste dispatch;
- no new action begins after cancellation is observed;
- session cleanup/release still runs;
- waits and shutdown have explicit bounds.

An unbounded whole-payload dispatch violates this contract.

## Modifier safety

Physical trigger modifiers may still be down when the trigger arrives.

ClipType must:

- never release the user's physical modifier keys;
- wait for trigger modifiers to be released within a bounded timeout;
- return a typed conflict/timeout result if a safe state is not reached;
- recheck conflicting modifier state before later actions when backend semantics require it;
- avoid introducing a broad global keyboard hook for this purpose.

## Humanized keyboard pacing

Keyboard and Code delivery use validated persistent `characters_per_second`, bounded `jitter_percent`, and opt-in corrected-typo probability.

- each original scalar/line-break/Tab action consumes its own pacing slot;
- a simulated wrong character, its Backspace, and the intended character are separate paced actions;
- jitter is independently bounded for each action;
- all pacing waits remain cancellation-aware;
- active sessions keep an immutable settings snapshot;
- deliberate typos are limited to eligible ASCII source actions and are not applied to non-ASCII text or Code navigation actions;
- typo mode is unsuitable for passwords, commands, terminals, administrative tools, or other exact-data entry.

## Unicode, line breaks, and Tab

Text semantics, not a US keyboard layout, are primary. Windows uses Unicode-oriented `SendInput` events plus explicit special keys where required. macOS uses bounded Core Graphics keyboard/text events.

Line break and Tab behavior are target-sensitive. Terminals may assign operational meaning to Enter; tests therefore use benign fixtures and documentation does not present arbitrary multiline terminal typing as universally risk-free.

## Bounded dispatch result

For one native action/batch, an adapter reports:

- complete;
- no native events accepted;
- partial native acceptance;
- progress unknown when native event counts cannot be mapped safely to a semantic prefix.

Partial or unknown results are never automatically retried. Results and diagnostics contain categories/counts only, never clipboard plaintext.

## UIPI and blocked input

Known evidence and diagnosis remain separate:

- when target-integrity evidence reliably proves a restricted relationship, report a security-boundary result before dispatch;
- when evidence is unknown and native insertion accepts no events, report blocked/native-cause-unknown rather than asserting one cause;
- ClipType does not change its privilege automatically to overcome the restriction.

## Clipboard acquisition

Current plain text is read only after the explicit trigger and target capture. ClipType does not continuously capture clipboard content and does not require a listener or history.

Transient clipboard-busy handling is bounded. During preparation, cancellation and the originally captured target remain relevant; contention must not create an indefinite wait.

The clipboard adapter copies bounded native text into owned sensitive memory, returns a content-blind revision witness, and releases native clipboard locks/handles before orchestration proceeds.

## Clipboard delivery contract

Clipboard mode deliberately uses the clipboard value that is already current.

1. acquire bounded current text and revision;
2. freeze the clipboard backend only if paste and revision-guard capability are available;
3. revalidate target, integrity, modifiers, cancellation, and expected revision;
4. send one balanced native Paste chord;
5. classify native progress conservatively and stop.

There is no ClipType clipboard write, temporary ownership, self-generated clipboard event, restore, or overwrite step. If the revision changed, abort before paste. This avoids a restoration race that could overwrite a newer external clipboard value.

## Retry policy

- clipboard acquisition may retry bounded transient busy failures;
- synthetic keyboard/Code input does not retry partial/unknown results as though idempotent;
- Paste dispatch is not blindly replayed after uncertain progress;
- permission, target-change, modifier, revision-change, and security-boundary outcomes do not retry blindly;
- a second trigger does not create a hidden queue.

## Content-free outcomes

The live coordinator returns to idle after contained terminal paths and exposes only statuses such as completed, busy, cancelled, target changed/evidence unavailable, modifier conflict, empty/non-text clipboard, revision changed/unavailable, unsupported input, known restriction, blocked cause unknown, partial/progress unknown, native failure, or internal invariant.

## Code-mode editor contract

Code mode is intentionally a destination-editor contract rather than target-content automation:

- ordinary auto-pair and auto-indent behavior is assumed;
- the planner never reads document text, selected text, caret content, DOM values, or editor configuration;
- matching generated closers are skipped only from source/context rules and bounded navigation actions;
- if cursor-navigation capability is unavailable or degrades, Code mode fails closed rather than falling back to Clipboard/Paste;
- exact named-editor support requires physical evidence and is not inferred from hosted model/native tests.

## Performance and responsiveness

Measure native action duration, text throughput, cancellation latency, focus-check cadence, message-loop responsiveness, clipboard acquisition latency, CPU, and memory. Performance work must not weaken target, modifier, cancellation, revision, privacy, or partial-result guarantees.
