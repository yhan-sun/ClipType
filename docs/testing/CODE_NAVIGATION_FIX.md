# Code navigation modifier-isolation candidate: verification

## Scope and baseline

Baseline: `683f7ab54f21d0881f2ef1c01ce7edd920a8eaa8` (`v0.2.0-beta.4`).
This candidate addresses macOS synthetic modifier-state coupling near the first
Code-mode Right -> Command+Right navigation. It also preserves specific failure
reasons through the Rust/Swift/Flutter boundary. No release is implied.

The user-provided educational Rust source is a `.txt` fixture for the injection
planner, not a Rust program compiled by tests. Its floating-point `Ord` example
has an unrelated type error; preserving input, not compiling it, is the test.

## Executable portable checks

From the repository root after applying the candidate:

```sh
python3 scripts/verify_code_navigation.py
python3 scripts/verify_bridge_completion.py
```

Requirements: Python 3.10+, Clang and Swift. The first command uses AddressSanitizer
and UndefinedBehaviorSanitizer by default; `--no-sanitizers` must be explicitly
requested for an environment without them. Missing compilers fail, not pass.
Neither command reads the system clipboard or sends real input.

The first check extracts actual production C-compatible input functions and
links them to a mock Quartz API. It covers event order, explicit flags, private
source selection, physical-vs-synthetic observation selection, the first
navigation followed by Return and text, UTF-16, allocation-failure cleanup,
permission/Secure Input rejection, paste revision checks, and repeated actions.

The second check compiles the actual RustSnapshot Swift structure using the
actual C header. It verifies 19 mappings/control cases and 7 C ABI assertions.
It does not link the Rust library or build Flutter.

## Required repository/platform gates (not run in the patch-authoring Linux environment)

Use the repository's pinned toolchain; do not replace it with a different version
and report the result as the pinned gate.

```sh
cargo fmt --all -- --check
cargo test --locked -p cliptype-core -p cliptype-platform -p cliptype-app
cargo test --locked -p cliptype-core --test code_mode_heap_regression
cargo test --locked -p cliptype-flutter-bridge
cargo clippy --workspace --all-targets --locked -- -D warnings
```

On macOS the bridge completion unit tests are enabled by `target_os = "macos"`.
A Linux run that excludes that module does not validate the new Rust mapping.
Run the full macOS workflow/build command documented in the existing P4 runner
README, including rebuilding the Rust static library rather than reusing an old
one. Then run:

```sh
cd apps/cliptype-flutter
flutter analyze
flutter test
```

Run the existing Windows regression workflow too: this patch does not change
Windows event handling, but shared/core tests must remain green.

## Physical editor verification (NOT RUN by patch author)

Record source SHA, package digest, macOS version, architecture, editor version,
language mode, auto-pair/indent settings, speed and exact completion category.
Use a new disposable document and the generated/test fixture only. Do not test
in a terminal or a real private document. Do not persist real clipboard text.

1. Start with physical modifiers released. In Code mode, run the full heapify
   fixture. Verify the second `if`, `heap_sort`, and `main` are all reached.
   Compare the controlled document content and newline counts, not just its last
   visible brace. An autogenerated closer does not prove source completion.
2. Test small nested blocks, an empty block, comments, strings, arrays, ordinary
   quote pairs, LF and CRLF at 1, 50, and 250 actions/s and with jitter.
3. Verify Right -> Command+Right passes only the intended generated line, the
   following Return is sent once, and following ordinary text carries no
   unintended Command action. Repeat enough times to expose timing variation.
4. Hold each real modifier before triggering; verify bounded settling/timeout.
   Press each during typing; verify remaining input stops and the physical key
   is not released. Compare hardware and combined flags only in a controlled
   native test; do not add keylogging or editor-text observation to production.
5. Switch application/window, close the target, revoke Accessibility, enable
   Secure Input where appropriate, cancel, and trigger twice. Existing safety
   outcomes must remain intact. Same-window logical-field limitations remain.
6. Exercise Keyboard and Clipboard modes to catch shared macOS helper
   regressions. Clipboard revision guarding and no-write behavior must remain.

Report specific categories such as `modifier_conflict`,
`target_evidence_unavailable`, `partial_input`, or `native_failure`. Partial or
unknown results must not be automatically retried. Do not interpret native event
posting as verified target-text delivery.

## Deliberately separate issues

This candidate does not claim to solve arbitrary language lexing, grouped `}}`
spread across different generated lines, indentation fidelity, editor completion
menus, or every double-newline report. Do not weaken focus protection or broaden
the compatibility contract to hide those cases.
